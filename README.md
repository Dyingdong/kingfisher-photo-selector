# Kingfisher-一个摄影照片筛选软件

一个在 macOS 上运行的本地工具，用于在后期处理前，从一批 RAW 照片里快速挑出**主体不清晰**的片子，并辅助判断主体是否锐利、对焦是否跑偏、画面为什么发虚，支持 Adobe Bridge 星级评分、标记拒绝与元数据写入。只支持 RAW，不扫描 JPG。

判定、主体识别、鸟种识别都在本机完成，**完全离线**：不上传照片、不调用任何网络服务，也不需要 API Key。鸟种识别用 BioCLIP 2 本地模型，支持导入时可选批量识别，以及对鸟类摄影照片人工圈选后单张识别。

## 名字的由来

Kingfisher（翠鸟）停在水边，能透过水面的波纹与反光，从杂乱背景里精准锁定水下的鱼，一击命中。这个软件做的事很像：在一批 RAW 照片里找到真正的主体、判断它是否合焦够锐，把没拍清楚的片子筛出去。翠鸟也是观鸟摄影里最经典的题材之一。

综合评分区给出建议星级、题材（自动识别、可手动改）和各维度得分，每个维度悬停可看依据；点「采用建议」即可把建议星级写入元数据。清晰判定保留为一行供复核，但不再占据主视觉。信息区默认高度保证能看到评分、拍摄参数和清晰判定，其余往下滚动或拖动分隔条查看。各区边缘可拖动调整大小：在同一批照片里手动调好的比例会一直保持（切换照片、重算灵敏度都不变），只有重新导入新的一批素材时才恢复到默认比例。

顶部「信息区：右侧 / 下方」按钮可切换信息区位置：**默认在画面最右侧竖排**——右侧栏默认宽度 380，拖动分隔条可调宽调窄并一直记住；点一下切回预览下方（原布局，高度分隔条拖动）。右侧窄栏里元素自动紧凑排列：短参数两列一行，镜头名太长整行放、最多两行不截断。

首次导入、重新分析和向已有文件夹添加照片时，软件逐张完成新照片的清晰度分析、预览缓存和拍摄信息识别。同一张照片共用 ImageIO 图像源，按各算法原有尺寸取图，对焦点每 16 张批量读取一次。已有分析记录直接恢复，人工评级在后台与照片 XMP 核对。旧记录缺失的信息单独补算，锐度网格损坏的照片单独重算。读完鸟种记录（开启识别时完成推理）后进入筛选，当前选中的照片立即请求原尺寸预览，原尺寸就绪后再逐张预取附近照片。平移、缩放和预览图更新只通知预览区。批量导入时每张只保留长边最多 192 像素的列表小图，放大查看使用独立的原尺寸预览缓存。

只按所选文件夹根目录的会话日志恢复历史。题材弹窗点「取消」会放弃这次导入并保留当前会话。会话日志按相对路径区分不同子目录的同名照片。旧日志中能唯一匹配的照片继续使用历史结果，重名且无法确认的照片重新分析。历史预览缺失时会后台补建，完成后当前照片可立即使用。关闭鸟种识别时只读取历史鸟种记录。自动说明、星级和标签写入同一侧车时依次合并。

## 各功能的简单原理

### 1. 合焦判断的核心：拉普拉斯方差

对每张照片，先解码成一张灰度小图（长边约 1200 像素），切成 28×28 像素的小块。对每一块计算**拉普拉斯方差**——可以粗略理解为「这块画面里边缘的陡峭程度」：边缘越清晰、细节越丰富，数值越高；画面越糊，数值越低。

- 取所有块里**最锐的 1%（P99）**作为这张照片的「最锐区」分数。用 P99 而不是平均值，是为了不被大面积平坦背景（天空、墙面）拉低——观鸟摄影时主体往往只占很小一块，这种情况很常见。
- 找出主体所在的块，算主体的锐度中位数与「最锐区」的比值。**主体比最锐区差很多**，就说明焦点可能没落在主体上。
- 再做一个辅助判断：把图像**人为再模糊一次**，看主体块的分数掉多少。如果本来就很低、再模糊也几乎不掉，说明那块本来就没有细节（不是「被拍糊」，而是「没东西可糊」），这时判为「整片偏软」要更谨慎。

整体判定还考虑了：中心区与主体区的锐度差、偏软块占比、方向性（用来识别运动模糊而非合焦问题）。

### 2. 判定基准：每张照片独立，不跟同批照片比

每张照片用**固定阈值 400** 这同一把尺子衡量，不按批次找基准——否则一批照片整体都糊时基准会被拉低，糊片反而全被放行。

这个 400 是在 Canon EOS R6m2 / R7 的 50 张、带人工真值的样本上标定出来的。**它是经验值，只在同类机型、镜头、题材上可靠；换设备或拍法后需要用真值重新标定**，不能当成通用标准。

界面底栏的灵敏度可理解为这把尺子的松紧：
- 严格 = 阈值 ×1.8，基准更高，更多照片会被判为主体偏软 / 整片偏软；
- 标准 = ×1.0；
- 宽松 = ×0.6，基准更低，判定更宽松。

拍鸟等小主体题材建议保持「标准」档，避免误杀。工具里还保留「设清晰基准」按钮，可指定一张你确认清晰的照片作为固定参考；默认不需要，日常用独立阈值即可。

### 3. 热力图怎么来的

同样按块的拉普拉斯方差上色，但有两个刻意的设计：

- **分母固定**：用「本图最锐区」和「合焦基准」中的较大者做标尺，而不是各图自己归一化。否则一张全糊的照片按自己的最高点拉伸后会满屏绿色，看起来反而很锐。
- **灰块表示「无法判断」**：某块再模糊一次分数几乎不掉、且本身分数很低，说明这里纹理太少（纯色天空、墙面），画成灰色，不当作「糊」也不当作「锐」。主体掩膜内的块颜色会加深，便于直接看你关心的部位。

颜色只是相对参考，不是绝对画质评分。悬停预览工具栏的「锐度热力图」开关可看颜色含义。

### 4. 主体定位与圈选

按优先级依次尝试，取第一个有效结果：

1. **AI 主体识别**（前景实例分割 + 分类，macOS 14+）：用 Apple Vision 把前景物体从背景里分出来并给出类别标签，能从「小鸟 + 大面积天空」这类稀疏主体里真正框出主体。对前景像素的覆盖率逐块计算权重，只评价真的有主体像素的块，避免包围盒里的背景把分数稀释。
2. **人脸检测**：适合人像。
3. **人体姿态检测**：不依赖露脸，背影 / 侧身 / 低头的人像也能认出「人是主体」。
4. **显著性区域**：视觉注意力图，框出的范围往往偏大，只作兜底。
5. **中心权重**：以上都没有时，按画面中心和三分点位置给权重。

只有前景分割、人脸这两种可信定位，主体锐度比才直接参与判定；显著性兜底时会退回中心区比，避免把「主体偏软、背景清晰」误放行。界面上会显示当前用的是哪种定位方式。

自动定位不准时，可以**在预览上按住 ⌃ Control + 左键拖框圈出主体**（修饰键可在顶部「快捷键」面板里改）：

- 工具会按圈选范围**重新计算这一张的判定**，主体清晰度、「人工圈选」等指标跟着圈选区走，黄框标注人工圈选的主体；
- **放大（⌘ 框选、双击对焦点）只是「看」的操作**：只改变预览缩放，不碰任何判定参数；
- 人工圈选记录**按照片持久保留**：切换照片或复位缩放后，黄框与相关评分参数仍按这张照片的圈选区恢复；青框（AI 主体）始终独立显示。

### 5. 对焦点

通过**项目内置的 exiftool** 读取 RAW 的 MakerNote。目前支持 **Canon**（AFInfo：合焦点编号、各点坐标/大小、对焦模式）；坐标原点在画面中心，代码里转换成画面左上原点的归一化坐标后画红框。

**依赖情况（无需额外安装）**：exiftool 及其 Perl 模块已随 App 一起打包，不依赖你在系统里另外安装 exiftool；运行时只用到 macOS 系统自带的 `perl`（所有 Mac 都有）。也就是说，从 Release 下载解压即用，不需要 `brew install exiftool`。读取对焦点时会在预览区右下角显示「读取相机对焦点信息中…」；若确实没有对焦点数据，预览上不画红框。非 Canon 的 RAW、DNG 代理或转档文件可能没有这些字段，或只保留旧数据，仅供参考，不要当作绝对准确的合焦位置。

> 实现细节：Perl 对含中文的脚本路径会解析失败，因此 exiftool 会先被复制到纯 ASCII 的临时目录再执行（并在同级建立 lib 软链接，每次读取都会校验软链是否指向当前 App 的库目录，换位置后自动重建），这个转换对用户透明。

### 6. 对焦方式判定与失误诊断

**对焦方式**（自动 / 手动）按相机记录判定：无镜头信息 → 手动；有镜头但没有对焦点记录 → 手动；相机 AFAreaMode 为 0 → 手动；其余 → 自动。

**对焦失误诊断**（信息区「清晰判定与判断依据」内，顺序为：对焦方式 → 主体发虚 → 失误提示）：

- **疑似跑焦**（自动对焦）/ **疑似对焦拧偏**（手动对焦）：需要同时满足——相机合焦点处的锐度不足全图最锐处的 35%、最锐块离合焦点有 8% 画幅以上的距离、主体本身不锐（显示锐度比 <25%）。悬停可看具体数值（焦点位置、各处锐度百分比）。注意：**故意虚化主体**的照片也会满足这些条件，气泡里会提醒自行确认。
- **手动对焦·主体偏虚**：手动对焦且相机没有合焦点记录时，用「主体虚 + 别处锐」判据提示手动对焦没拧到位。
- **整片偏软**：整张都不够锐时，更像整体没对上而不是拧偏。
- **自动对焦没有失误迹象时，失误行整行不显示**；手动对焦无失误才显示「未见明显拧偏」。

### 7. 主体发虚与快门提示

主体清晰度低于最锐处 35% 时，无论自动还是手动对焦，信息区都会给一行黄色「主体发虚」提示，并按优先级推断原因（悬停看完整依据）：

- 快门明显慢于安全快门（1/等效焦距）1 档以上 + 拖影明显 → **疑似快门太慢**（手抖或主体在动）；
- 快门慢但拖影不明显 → **疑似手抖**（快门太慢）；
- 快门正常但拖影 >1.5 → **疑似主体移动快**；
- 以上都不是 → **疑似焦点没落在主体上**。

主体清楚但快门确实偏慢时，才单独显示一行「快门偏慢」提示；有发虚原因时两者合并为一条，不重复。

### 8. EXIF 与白平衡

- **拍摄参数**用 ImageIO 直接读 EXIF / TIFF 字典。ISO 兼容 CR3 的 `ISOSpeed` 和 DNG 的 `ISOSpeedRatings` 两种写法；快门时间格式化成 `1/2000s` 这样的形式。
- **等效焦距**：佳能 APS-C 半画幅微单（EOS R7/R10/R50、M 系列等）的焦距旁会显示等效值（×1.6，如 800mm → 等效 1280mm）；全画幅（如 R6m2）与其他品牌不显示。
- **白平衡**是本地统计：取全图（和人脸框内）的 R/G、B/G 通道比值，直接给出**结论**——明显偏黄（红蓝差 >0.20）、偏黄（>0.06）、偏蓝（<-0.06）、明显偏蓝（<-0.20）或接近中性；同时统计高光裁剪（通道 ≥250）和死黑（≤6）占比。它反映的是**画面颜色的统计倾向，不是相机的 K 值，也不能替代专业校色**。白平衡 / 曝光评分维度和参考区块仅人像题材显示（拍鸟、风光题材下隐藏）。

### 9. 星级评分 / 拒绝 / 删除 / 撤销 / CSV

- **RAW**：只生成同名 `.xmp` 侧车文件，原片不动。
- 「写入 Bridge 元数据」写入内容：判定原因写入 `dc:description` 和 `photoshop:Instructions`；**判定词写入 `xmp:Label` 标签字段**（主体清晰/焦点正常/整片偏软/景深不足/主体偏软/主体拖影，照片已有标签时不覆盖）。识别到鸟种时在同一标签后追加 `/ 鸟种`（如 `主体清晰 / 黑鹳`），人工改鸟种只替换这一段、一键清除只摘鸟种段。Bridge 的标签按文本匹配显示：在 Bridge「偏好设置 → 标签」里把 5 个标签名改成对应判定词，Bridge 就会按词显示颜色并支持按名筛选；未改设置或对不上的词显示白标（不影响文件里的文字本身，exiftool 等工具都能直接读出）。**不写任何关键词**（`dc:subject` 已停用，避免干扰你已有的 Bridge 关键词体系）。已有的关键词、说明、星级都会保留。标签和星级兼容 XMP 属性与元素两种写法。
- **星级评分**：支持 Adobe Bridge 的 0~5 星评分（**⌘1~⌘5** 评星、**⌘0** 清除），即时写入 `xmp:Rating`，可在 Adobe Bridge / Lightroom 里直接按星筛选；只改星级，不会覆盖已有的质检说明、关键词和颜色标签。
- **拒绝标记**：点「拒绝」按钮标记/取消，写入 `xmp:Rating=-1`（与 Adobe Bridge 的 Reject 语义一致）。
- **删除废片**：底部「删除当前照片」或 **⌘⌫**（Delete），删除选中的 RAW，并自动查找同目录下同文件名（不同扩展名）的 JPG 一起处理；文件**移到废纸篓**。删除前有确认对话框，列出将要处理的文件。批量删除逐个确认结果，移动失败的照片会保留在列表中，并保留人工圈选和题材记录。
- **撤销删除 ⌘Z**：把最近一次删除的文件从废纸篓**原样搬回原位置**（RAW + 连带删除的 JPG 一起），并恢复照片列表中的判定、人工圈选、题材及排除状态。原位置有同名文件时会提示恢复失败，移开同名文件后可重试。只支持撤销最近一次删除。
- 写入前会把原元数据备份到**照片所在目录**（`<照片名>.before.xmp` / `.before-rating.xmp` / `.before-desc.xmp`）；已有备份时**不覆盖**——永远保留第一次写入前的原始状态。界面上「打开写入前备份」按钮直接打开当前照片所在目录。
- 列表里可对单张点「排除写入」，避免误标。
- **CSV 报告**与命令行工具共用同一套列定义（含最锐区 P99、判定基准、主体/中心锐度比、方向性、灵敏度、判定原因、对焦失误提示、完整路径等），带 BOM，Excel / Numbers 直接打开不乱码；可填「人工真值」列后用 `Tools/verify.py` 复核判定质量。

### 10. 综合评分选片（拍鸟 / 风光 / 人像）

综合评分用来直接选片。它借鉴了慧眼识鸟「清晰度 + 整体质量双达标才给高星」的思路，但每个维度都取自本工具已经能解释、能复核的指标，不引入无法验证的美学打分模型。

- **题材判定链**（依据显示在题材下方，可核对）：
  1. **对焦点处识别到什么**（最高优先级）：人脸 / 相机用人脸对焦模式 → 人像；鸟或鸟种 → 拍鸟；明确的大场景（水面、山、建筑等，典型是「长焦拍风光」）→ 风光（例外：画面主体确认是人 → 人像；超长焦 ≥400mm 且分割出明确前景小主体 → 拍鸟）。对焦点 / AI 主体也能认出**花**和**具体动物**（马 / 兔 / 狗等），这些一律归到风光题材，不新增题材类型；
  2. 对焦点认不出鸟时，用 Vision 专门的动物检测复核——小飞鸟常被蓝天淹没、通用分类认不出，动物检测器仍能检出；**但现在会看 Vision 返回的具体类别**：检出的是鸟才判鸟，检出明确非鸟动物（猫 / 狗 / 兔 / 马等）则不判鸟，交后续主体识别 / 评分兜底——避免长焦下把兔子竖耳剪影误判成拍鸟（实测草地兔子曾被 Vision 认成猫 58~73%，现已据此归风光）。另外深色鸟（乌鸦 / 渡鸦）抠图后分类常给出乱标签，还有整图**多鸟种标签互证**兜底：长焦下出现多个鸟种标签互证、且没有具体非鸟动物标签时采纳为鸟（9163~9215 那组黑鸟 5/5 判鸟）；
  3. **长焦下小裁块二次复核**：对焦点 30% 裁块没认出明确内容（unknown）且没有具体动物标签时，以对焦点为中心收紧到 15% 裁块再识别一次——目标在裁块中的相对占比变大，标签置信度随之上升，部分远距离小鸟（枝头鸟 / 极小飞鸟）可被正式识别而不再靠焦距兜底（实测：远距离枝头鸟 / 飞鸟救回，风光 / 人像对照组零误伤）；门槛与 30% 裁块完全一致，识别不出仍走原兜底。30% 裁块已认出明确风景（水面 / 陆地等）或具体动物（兔 / 马等）时不复核——兔子头部在小裁块里会被认成鸟，动物检测在小裁块上也拦不住，只能挡在门外；
  4. **画面里有没有人**：人体姿态检测（不依赖露脸），且人占画面较大（高度 ≥35%）→ 人像，背影 / 侧身 / 低头也能认出；**多个人且人是主体（景区游客）不判人像**，仍按风光走；风景里的小人不会误判；
  5. **长焦兜底需要「鸟证」**：长焦镜头只有在识别到鸟（对焦点语义或 AI 主体）时才判拍鸟，否则按风光——长焦拍的花朵、雪山不再被硬判成拍鸟；
  6. 以上都没有，才退回原规则（前景小主体 / 观鸟长焦镜头 → 拍鸟，其余 → 风光）。

  题材顶部可手动改成正确值。**每次手动改题材，软件会记住这次的纠正**（对焦点标签签名等特征存本地 JSON，`~/Library/Application Support/Kingfisher-PhotoSelector/genre_corrections.json`）：之后遇到特征**高度相似**的照片（对焦点分类的 top 标签一致且另有标签重合，或总重合足够多）才优先按你以往的判断来判，识别依据会注明「参考了你以往 N 次同特征纠正」。这是规则层的经验积累、不是重新训练模型——每个纠正样本都可直接查看，题材区有「纠正记忆 N 条 · 清空」按钮可一键清空。
- **评分维度**（0~100 分，权重随题材变）：主体清晰度、整体锐度（热力图口径）、对焦准确度、白平衡/曝光（仅人像）。每项悬停有依据和关键数值，可自己核算。
- **主体清晰度是硬门槛**：主体偏软、主体拖影的片子无论其他维度多高，星级都被压到 1~2 星——与慧眼识鸟「失焦直接降星」一致；**整片偏软只轻压到 ≤3 星**（整片都软时主体未必真的废，常见于天空小主体记录照，是否保留由你自己判断）。这也是选片最可靠的一道筛子。
- **建议星级**：点「采用建议」把建议星级写入 `xmp:Rating`，之后在 Bridge / Lightroom 里按星排序即可。

> **真值复核**：50 张带人工真值样本上，37 张好片里 36 张评到 3 星以上，13 张废片 13 张全部压在 2 星以下（唯一例外是一张被重度裁切、几乎无可测细节的片子，属已知能力边界）。复核脚本：`Tests/score_probe_real.swift`（新版支持按目录结构 / CSV 两种真值来源；50 张样本原目录已不在磁盘，现用 test3 目录真值回归）。

### 11. 元数据「说明」自动写入

**切换照片时**，自动把上一张的分析结果写进它元数据的「说明」（`dc:description`，Bridge / Lightroom 的说明字段），内容顺序：

1. **鸟种 / 鸟类类别**（仅拍鸟题材认出时）：BioCLIP 2 本地识别 / 人工确认的鸟种优先（注明来源），没有时才用 AI 主体识别或对焦点语义给的类别；能认出鸟种给中文名（鹭、鸭、鸥等），只认出「鸟」认不出种时如实写「识别到鸟（具体鸟种认不出）」；
2. **评星依据**：建议星级、总分、主要短板（如「建议 4 星（总分 78），短板：主体清晰度 55 分」）；
3. **清晰判定**：判定结论 + 白话原因。

**安全性设计**（已实测验证）：

- 只动 `dc:description` 这一个字段：关键词、星级、颜色标签、你自己手写的说明**全部保留**——软件写入的说明会按标记刷新，只替换自己这一段；
- RAW 走同名 `.xmp` 侧车（不改原片），JPG 内嵌 XMP；
- 写入前自动备份到照片所在目录（`<照片名>.before-desc.xmp`，已有备份不覆盖）；
- 不想自动写说明时可关掉「切换时自动写说明」开关（清除标记前建议先关，否则切照片会重新写入）；
- 侧车文件损坏、解析失败时**拒绝写入**并提示，不会覆盖原数据；
- 文件已被删除（进了废纸篓）时跳过，不会往废纸篓里的文件写侧车。

> **关于雄雌**：系统 Vision 分类器和 BioCLIP 2 都能认鸟种，但**分不出雄雌**（繁殖羽 / 羽色差异需要专门训练的模型或人工判断），说明里不硬猜。

### 12. 鸟种识别（BioCLIP 2 本地）

- **导入时批量识别**。选择「自动识别题材」或「鸟类摄影」时才显示「同时识别鸟种」，每次导入默认不勾选。开启后为本次新导入、最终题材为鸟类摄影的照片识别鸟种。已有可靠鸟种记录直接恢复。
- **人工圈选后单张识别**。自动判断或手动设为鸟类摄影的照片，完成人工圈选即可按新范围识别。无论导入时有没有勾选、这张有没有跑过自动识别，圈选都可以重新识别。已有人工确认优先。切图、放大和改题材本身不触发推理。
- **本地模型**：BioCLIP 2（open_clip ViT-L/14）图像塔转成 Core ML（约 580MB），文本塔预计算成 1.1MB 特征文件；候选 376 种（373 种中国鸟 + 彩鹮 / 细嘴鸥 / 银鸥）。整图与主体框各跑一次取更高置信；**置信 ≥ 0.50 直接采纳；低于 0.50 时仅当两路 Top1 一致（日志标注「整图与主体框互相印证」）且置信 ≥ 0.45 才放宽采纳**（可恢复大山雀 49.3% 这类正确结果）。放宽下限 0.45 仍会挡住暗光 / 空画面误认（实测黑胸鸫 26.8%、普通翠鸟 26.2%），更低的不给鸟名、不写标签。历史日志按同一口径读回：人工确认始终优先，本地 ≥ 0.50 直接可信，0.45–0.50 且注明「互相印证」也可信；其余低置信旧记录不再读回。纯本地推理，无网络、无 API Key、无钥匙串。
- **准确边界**：实测黑鹳 1.00、灰喜鹊 0.99 正确；细嘴鸥那张把「鸥嘴噪鸥」排第一、细嘴鸥第二；凤头麦鸡会被高置信误判成彩鹮（0.83）。结果只作参考，**必须放大原图人工确认**，人工确认不被自动结果覆盖。
- **标签与日志**：识别结果写进 `xmp:Label`（判定词 + ` / 鸟种`，如 `主体清晰 / 黑鹳`），写入前备份 `.before-bird.xmp`；照片根目录生成可见日志 `kingfisher-birds.log`，逐条累积识别 / 人工确认和照片根目录绝对路径；顶部「鸟种记录」按钮导出独立 CSV。主报告 CSV 末尾另加识别鸟种、置信、来源、依据、Top3 五列。

### 13. 悬停提示与快捷键

- **悬停提示**：信息区任意一行鼠标停留满 1 秒，弹出以**该指标名**为标题的白话解释气泡（系统 popover：不透明、跟随深浅色、始终完整显示在屏幕内、横向排版），离开立即消失。判断依据区所有指标都有解释。
- **叠加层开关**：`H` 热力图、`F` 对焦点、`G` 九宫格、`D` 对角线；顶部工具栏这四个开关现在直接显示对应字母（小灰字），不用记也一眼可见；
- **评星**：`⌘1`~`⌘5` 打 1~5 星，`⌘0` 清除星级；
- **删除**：`⌘⌫`（Delete）删除当前照片（仍走确认弹窗），`⌘Z` 撤销最近一次删除；
- 框选手势的修饰键（默认 ⌘ = 放大、⌃ = 圈选主体）可在顶部「快捷键」面板里改成 ⌥ / ⇧。

## 怎么用

### 方法一：下载编译好的 App（推荐）

从本仓库 [Releases](https://github.com/Dyingdong/kingfisher-photoselector/releases) 下载最新版，解压双击即可。当前发布包仅支持 **Apple Silicon（arm64）**。

若提示「来自身份不明的开发者」，右键 → 打开 → 弹窗里点打开；或执行：

```bash
xattr -cr "/path/to/Kingfisher-PhotoSelector.app"
```

### 方法二：从源码编译

需要 Apple Silicon Mac，以及 Xcode 命令行工具（`xcode-select --install`）：

```bash
git clone git@github.com:Dyingdong/kingfisher-photo-selector.git
cd kingfisher-photo-selector
./build.sh
```

`build.sh` 会编译 GUI App 和命令行工具 `kingfisher-photoselector`，并把内置的 exiftool 打进 App 资源里。用 `ditto` 打包 App 可保留 macOS 扩展属性：

```bash
ditto -c -k --sequesterRsrc --keepParent "Kingfisher-PhotoSelector.app" Kingfisher-PhotoSelector.zip
```

### 界面操作步骤

1. 把照片文件夹拖进窗口，或点「选择文件夹」；也可一次拖入多张照片。
2. 左侧默认「只看需留意」（主体偏软 / 整片偏软 / 景深不足），取消勾选可看全部；点某张在右侧查看。
3. 看热力图判断主体锐度；**滚轮向下滚动放大、向上滚动缩小（以鼠标所在位置为中心）**。预览手势：
   - **⌘ + 左键拖框** = 放大选中的区域（可继续框选放大）；**右键拖框**同样放大。放大只改变显示，不影响判定。
   - **⌃ Control + 左键拖框** = 圈选主体重判这一张（主体清晰度等指标按圈选区算，黄框标注）。
   - **按住左键拖动** = 平移画面（按住空格再拖也可以）。
   - **单击** = 复位到 1×。
   - **双击** = 放大到相机对焦点所在区域（无对焦点数据时退回主体框）。
4. 信息区「清晰判定与判断依据」里的指标全部直接显示（主体清晰度、画面中心清晰度、合格线、发虚区域、拖影、对焦方式、主体发虚原因等），鼠标停留 1 秒弹出以指标名为标题的白话解释。
5. 自动主体定位不准时，用圈选手势纠正；各手势的修饰键可在顶部「**快捷键**」面板里改（若系统开了「Control + 点击 = 右键」，⌃ 会被系统拦截，改用别的键即可）。
6. 底部调灵敏度（严格 / 标准 / 宽松）会即时重算全部结果。
7. 看**综合评分区**：确认题材对不对（自动识别不准就手动改，软件会记住纠正），看建议星级和各维度得分；构图用默认开启的「九宫格」「对角线」辅助线人工判断（觉得碍眼可用 `G` / `D` 关掉）。
8. 认可建议就点「**采用建议：打 N 星**」写入 Bridge 星级；也可用 ⌘1~5 手动评星或点「拒绝」。**切换照片时**评星依据、合焦信息、鸟种会自动写进照片元数据的「说明」。确认后点「写入 Bridge 元数据」（批量质检标记）或「导出 CSV 报告」；要删片用底部「删除当前照片」或 ⌘⌫，删错了 ⌘Z 撤销。

### 命令行批量处理

`build.sh` 生成的 `kingfisher-photoselector` 与 App 共用同一套判定和报告格式：

```bash
./kingfisher-photoselector /path/to/photos -o report.csv -s 1.0
```

参数：`-o` 输出 CSV、`-s` 灵敏度（默认 1.0）、`-a` 指定清晰参考片（可选，默认不需要）、`--faces` 优先按人脸定位主体。

### 用真值复核

`Tools/verify.py` 提供四个子命令：

- `truth`：用人工真值算混淆矩阵、临界样本、建议灵敏度
- `drift`：检验判定是否依赖批次构成
- `degrade`：模糊梯度，检验分数与判定的单调性和拐点
- `bytes`：检查写入的 XMP 是否合法、字段齐全、结构完好

仓库内的 `真值-real_v5.xlsx`、`真值-整理版50张.csv`、`标定样本画像.csv` 是标定和复核用的样本数据。

## 边界与注意事项

- **判定是辅助，不是结论。** 它是基于 50 张真值样本调出来的经验规则，换机型/镜头/题材后应重新标注标定；临界片一定要人眼看一眼再决定是否删。
- 热力图是相对参考，不是相机 K 值或测光表；灰块表示该处纹理不足、无法判断。
- 对焦点目前主要支持 Canon RAW，其他来源仅供参考或没有数据。对焦点语义**只决定题材权重，不改变主体清晰度判定**（实测真废片多数焦点就在主体上，焦点位置≠主体清晰）。
- 白平衡是颜色统计倾向，不是色温 K 值。
- 模糊和景深不足、运动模糊在画面上表现相近，工具会给出区分提示，但最终取舍仍需结合拍摄意图。
- **题材识别的已知边界**：
  - 长焦没识别到鸟就按风光判——真拍到鸟但检测器没认出的片子会被判成风光，手动改题材即可；
  - 远距离枝头小鸟（鸟只占画面约 2%）是系统 Vision 的**物理极限**：实测对焦点裁块里画面 80~98% 是树枝/植物，鸟标签置信度只有 4~11%（判定门槛 20%），动物检测完全零检出，提高分辨率也无效。为救回这类片子新增了「15% 小裁块复核」：部分鸟标签能到 18~28% 的枝头鸟 / 飞鸟可被正式识别（不再需要手动改题材）；鸟标签更低或为零的片子（约一半）救不回，仍判风光，手动改题材即可；
  - 极小剪影鸟（占画面 <0.5% 且无纹理的深色飞鸟）是 Vision 的物理极限：前景分割能框出它（真实占比 0.04%~0.35%），但抠图分类与动物检测都认不出，只能靠「长焦 + 极小前景主体」兜底或手动改题材。识别依据里的前景占比显示一位小数（如 0.3%）——此前显示 0% 是整数截断的展示 bug，已修复；
  - Vision 会把兔子的竖耳剪影认成猫（实测 58~73%），这是系统模型的局限：界面按 Vision 实际返回的类别如实显示「猫」，**不臆造成「兔」**；但题材判定上已按「明确非鸟动物」处理，归到风光，不会误判成拍鸟；
  - 人被道具大面积遮挡（如舞龙）时，Vision 的姿态 / 分割 / 人脸检测全部失效（实测分辨率提到 3072 也检不出），属系统框架极限，手动改题材；
  - 纠正记忆只在特征高度相似时才套用，不会大面积改写算法判定。
- **鸟种与雄雌**：BioCLIP 2 只覆盖 376 种候选，高置信也可能认错（实测凤头麦鸡→彩鹮 0.83），人工确认为准；极小、遮挡或复杂背景的鸟仍会漏。雄雌（羽色差异）分不出，说明里不硬猜。
- **元数据写入**：写入前会自动备份到照片所在目录（已有备份不覆盖，永远保留第一次写入前的原始状态）；RAW 只写侧车文件，不改动原片；「说明」只替换软件自己标记的段落，你手写的内容、星级、关键词、标签都保留（本软件已停用关键词写入，你已有的关键词不受影响）；已有 XMP 读取或解析失败时会跳过该张并报错。JPG 内嵌和同名侧车分别保留各自的元数据；清除时先备份，再写有本软件标记的位置。评分/拒绝会单独备份原 XMP 到照片所在目录。
- **清除本软件标记**：「清除本软件标记 (N)」按钮一键清掉本软件写入的全部内容——说明与 Instructions 里的「[Kingfisher-PhotoSelector]」「[合焦质检]」段、本软件写的判定词标签（含追加的鸟种段、旧版英文颜色标签）；你自己的说明、关键词、星级、拒绝标记、手动打的标签一律不动；没有本软件标记的照片不写文件。清除后如需再让软件写说明，切照片时会自动重写（不想重写就先关「切换时自动写说明」开关）。
- 删除会进废纸篓而非直接抹除，⌘Z 可撤销最近一次；但废纸篓容量有限，清空后不可恢复，删片前仍建议确认。
