# 摄影照片筛选工具

一个在 macOS 上运行的本地工具，用于在后期处理前，从一批 RAW 照片里快速挑出**未合焦**的片子，并辅助判断主体是否锐利、对焦是否跑偏、白平衡是否偏色，支持按 Adobe Bridge 的方式打分、标记拒绝并写入元数据。只支持 RAW，不扫描 JPG。

所有分析都在本机完成，不上传照片，不调用网络服务。

## 能做什么

| 功能 | 说明 |
| --- | --- |
| 合焦初筛 | 扫描整个文件夹（含子文件夹），逐张给出判定：合焦 / 全片未合焦 / 主体未合焦 / 景深不足 / 运动模糊 / 无法解码 |
| 锐度热力图 | 把画面切成小块，用颜色标出各处的锐利程度，直接看想要的主体是否够锐 |

| Bridge 标记 | 把"未合焦"关键词和判定原因写入照片元数据，可在 Bridge 里按关键词/红色标签筛出 |
| CSV 报告 | 导出每张照片的完整判定指标，便于复核、统计、留档 |

| 对焦点语义识别题材 | 先看相机对焦点处识别到什么（人脸/鸟/风景）再定题材，长焦拍风光不再误判成拍鸟；识别依据可核对 |

| 拒绝标记 | 一键标记"拒绝"（Bridge Reject），写入 `xmp:Rating=-1` |
| 删除废片 | 删除选中的 RAW，并自动一并删除同目录下同名的 JPG；文件移到废纸篓，可恢复 |

界面分为三个区域：左侧照片目录（缩略图 + 短文件名 + 判定），右上原图预览（叠加热力图/对焦框/构图辅助线），右下信息区（从上到下：Bridge 评分条 → 拍摄参数 → **综合评分** → 合焦判定 → 判断依据 → 白平衡/曝光参考）。

综合评分区在星星行右侧紧挨着「采用建议：打 N 星」按钮，看完星一眼就能写入 Bridge 星级；题材（自动识别、可手动改）和各维度得分条都在下方，每个维度悬停可看依据。合焦判定保留为一行供复核，但不再占据主视觉。信息区默认高度保证能看到评分、拍摄参数和综合评分，其余往下滚动或拖动分隔条查看。各区边缘可拖动调整大小：在同一批照片里手动调好的比例会一直保持（切换照片、重算灵敏度都不变），只有重新导入新的一批素材时才恢复到默认比例。

顶部「信息区：下方 / 右侧」按钮可切换信息区位置：默认在预览下方（原样），点一下改到画面最右侧竖排，预览与信息区的分界可拖动，窄栏里评分、参数等元素会自动紧凑排列。

## 各功能的简单原理

### 1. 合焦判断的核心：拉普拉斯方差

对每张照片，先解码成一张灰度小图（长边约 1200 像素），切成 28×28 像素的小块。对每一块计算**拉普拉斯方差**——可以粗略理解为"这块画面里边缘的陡峭程度"：边缘越清晰、细节越丰富，数值越高；画面越糊，数值越低。

- 取所有块里**最锐的 1%（P99）**作为这张照片的"最锐区"分数。用 P99 而不是平均值，是为了不被大面积平坦背景（天空、墙面）拉低——拍鸟时主体只占很小一块，这种情况很常见。
- 找出主体所在的块，算主体的锐度中位数与"最锐区"的比值。**主体比最锐区差很多**，就说明焦点可能没落在主体上。
- 再做一个辅助判断：把图像**人为再模糊一次**，看主体块的分数掉多少。如果本来就很低、再模糊也几乎不掉，说明那块本来就没有细节（不是"被拍糊"，而是"没东西可糊"），这时判为"未合焦"要更谨慎。

整体判定还考虑了：中心区与主体区的锐度差、偏软块占比、方向性（用来识别运动模糊而非合焦问题）。

### 2. 判定基准：每张照片独立，不跟同批照片比

早期版本用"本批照片锐度的第 75 百分位"当基准，问题是：如果一批照片整体都糊，基准也会被拉低，糊片反而全被放行。现在改成**固定阈值 400**，每张照片用同一把尺子衡量。

这个 400 是在 Canon EOS R6m2 / R7 的 50 张、带人工真值的样本上标定出来的。**它是经验值，只在同类机型、镜头、题材上可靠；换设备或拍法后需要用真值重新标定**，不能当成通用标准。

界面底栏的灵敏度可理解为这把尺子的松紧：
- 严格 = 阈值 ×1.8，基准更高，更多照片会被判为未合焦；
- 标准 = ×1.0；
- 宽松 = ×0.6，基准更低，判定更宽松。

工具里还保留"设清晰基准"按钮，可指定一张你确认清晰的照片作为固定参考；默认不需要，日常用独立阈值即可。

### 3. 热力图怎么来的

同样按块的拉普拉斯方差上色，但有两个刻意的设计：

- **分母固定**：用"本图最锐区"和"合焦基准"中的较大者做标尺，而不是各图自己归一化。否则一张全糊的照片按自己的最高点拉伸后会满屏绿色，看起来反而很锐。
- **灰块表示"无法判断"**：某块再模糊一次分数几乎不掉、且本身分数很低，说明这里纹理太少（纯色天空、墙面），画成灰色，不当作"糊"也不当作"锐"。主体掩膜内的块颜色会加深，便于直接看你关心的部位。

颜色只是相对参考，不是绝对画质评分。

### 4. 主体定位

按优先级依次尝试，取第一个有效结果：

1. **前景实例分割**（macOS 14+）：用 Apple Vision 把前景物体从背景里分出来，能从"小鸟 + 大面积天空"这类稀疏主体里真正框出主体。对前景像素的覆盖率逐块计算权重，只评价真的有主体像素的块，避免包围盒里的背景把分数稀释。
2. **人脸检测**：适合人像。
3. **显著性区域**：视觉注意力图，框出的范围往往偏大，只作兜底。
4. **中心权重**：以上都没有时，按画面中心和三分点位置给权重。

只有前景分割、人脸这两种可信定位，主体锐度比才直接参与判定；显著性兜底时会退回中心区比，避免把"主体未合焦、背景清晰"误放行。界面上会显示当前用的是哪种定位方式。

如果自动定位不准，可以**在预览上按住 ⌃ Control + 左键拖框圈出主体**，工具会按圈选范围重新计算这一张的判定，并在报告里标注"人工圈选"。放大和圈选各自的修饰键都可以在顶部「快捷键」里修改。

### 5. 对焦点

通过**项目内置的 exiftool** 读取 RAW 的 MakerNote。目前支持 **Canon**（AFInfo：合焦点编号、各点坐标/大小、对焦模式）；坐标原点在画面中心，代码里转换成画面左上原点的归一化坐标后画红框。

**依赖情况（无需额外安装）**：exiftool 及其 Perl 模块已随 App 一起打包，不依赖你在系统里另外安装 exiftool；运行时只用到 macOS 系统自带的 `perl`（所有 Mac 都有）。也就是说，从 Release 下载解压即用，不需要 `brew install exiftool`。读取对焦点时会在预览区右下角显示"读取相机对焦点信息中…"；若确实没有对焦点数据，预览上不画红框。非 Canon 的 RAW、DNG 代理或转档文件可能没有这些字段，或只保留旧数据，仅供参考，不要当作绝对准确的合焦位置。

> 实现细节：Perl 对含中文的脚本路径会解析失败，因此 exiftool 会先被复制到纯 ASCII 的临时目录再执行（并在同级建立 lib 软链接，每次读取都会校验软链是否指向当前 App 的库目录，换位置后自动重建），这个转换对用户透明。

### 6. EXIF 与白平衡

- **拍摄参数**用 ImageIO 直接读 EXIF / TIFF 字典。ISO 兼容 CR3 的 `ISOSpeed` 和 DNG 的 `ISOSpeedRatings` 两种写法；快门时间格式化成 `1/2000s` 这样的形式。
- **白平衡**是本地统计：取全图（和人脸框内）的 R/G、B/G 通道比值，据此判断偏暖、偏冷、偏洋红、偏绿；同时统计高光裁剪（通道 ≥250）和死黑（≤6）占比。它反映的是**画面颜色的统计倾向，不是相机的 K 值，也不能替代专业校色**。

### 7. Bridge 星级 / 拒绝 / 删除 / CSV

- **RAW**：只生成同名 `.xmp` 侧车文件，原片不动。
- 写入内容：`dc:subject` 加关键词「未合焦」、判定原因写入 `dc:description` 和 `photoshop:Instructions`，可选加 `xmp:Label=Red` 红色标签。已有关键词、标签、星级都会保留。
- **星级评分**：在右下信息区点 5 颗星打分（0~5 星），再点当前星级会清零；评分即时写入 `xmp:Rating`，不需要再按"写入 Bridge 元数据"。评分只改星级，不会覆盖已有的质检说明、关键词和颜色标签。
- **拒绝标记**：点"拒绝"按钮标记/取消，写入 `xmp:Rating=-1`（与 Adobe Bridge 的 Reject 语义一致）。
- **删除废片**：底部"删除当前照片"会删除选中的 RAW，并自动查找同目录下同文件名（不同扩展名）的 JPG 一起处理；文件**移到废纸篓**，可从废纸篓恢复。删除前有确认对话框，列出将要处理的文件。工具只扫描 RAW，JPG 只作为连带清理对象出现，不会单独列在照片目录里。
- 写入前会先把原元数据备份到 `应用程序支持/FocusScreener/backups/<时间戳>`，界面上有按钮直接打开。
- 列表里可对单张点"排除写入"，避免误标。

CSV 报告与命令行工具共用同一套列定义（含最锐区 P99、判定基准、主体/中心锐度比、方向性、灵敏度、判定原因、完整路径等），带 BOM，Excel / Numbers 直接打开不乱码；可填"人工真值"列后用 `Tools/verify.py` 复核判定质量。

### 8. 综合评分选片（拍鸟 / 风光 / 人像）

原信息区的"合焦结论"改成**综合评分**，用来直接选片。它借鉴了慧眼识鸟"清晰度 + 整体质量双达标才给高星"的思路，但每个维度都取自本工具已经能解释、能复核的指标，不引入无法验证的美学打分模型。

- **题材**：先看**对焦点处识别到什么**（这是最高优先级，依据显示在题材下方可核对）：
  1. 对焦点在人脸 / 相机用人脸对焦模式 → 人像；
  2. 对焦点处识别到鸟或鸟种（如鹭、鸦，带置信度）→ 拍鸟；
  3. 对焦点处是天空、水面、山、田野等大场景（典型是「长焦拍风光」）→ 风光；
  4. 对焦点识别不出来时，才退回原规则（前景小主体 / 打鸟镜头 / 超长焦 → 拍鸟，其余 → 风光）。
  
  题材顶部可手动改成正确值。拍鸟看主体清晰度+锐度；风光看主体清晰度+整体锐度，构图交给辅助线人工判断；人像看对焦点、人脸清晰度和白平衡。
- **等效焦距**：拍摄参数里，佳能 APS-C 半画幅微单（EOS R7/R10/R50、M 系列等）的焦距旁会显示等效值（×1.6，如 800mm → 等效 1280mm）；全画幅（如 R6m2）与其他品牌不显示。目前只支持佳能微单。
- **评分维度**（0~100 分，权重随题材变）：主体清晰度、整体锐度（热力图口径）、对焦准确度、白平衡/曝光。每项悬停有依据和关键数值，可自己核算。
- **合焦是硬门槛**：失焦、拖影的片子无论其他维度多高，星级都会被压到 1~2 星——与慧眼识鸟"失焦直接降星"一致。这也是选片最可靠的一道筛子。
- **建议星级落到 Bridge**：点「采用建议」把星级写入现有 `xmp:Rating`（还是最上面那个 5 星评分条），之后在 Bridge/Lightroom 里按星排序即可。

> **已知边界**：对焦点语义**只决定题材权重，不改变合焦判定**（实测 9 张真废片里 7 张焦点就在主体上，焦点位置≠合焦）。对焦点的鸟识别用的是通用图像分类（Vision），没有专门的「鸟身体部位」检测器：对大而清楚的鸟识别率高（实测鹭/鸦等 20%~64%），对很小、复杂背景或被裁掉的鸟会漏；漏了就退回原规则，不会硬猜。识别不准时题材可手动改。构图没有可靠自动打分依据，不计入分数，用工具栏的九宫格/对角线辅助线人工看。所有阈值都是在这批 Canon R6m2/R7 样本上标定的经验值，换设备需用真值重新标定。
>
> **真值复核**：50 张带人工真值样本上，37 张好片里 36 张评到 3 星以上，13 张废片 13 张全部压在 2 星以下（唯一例外是一张被重度裁切、几乎无可测细节的片子，属已知能力边界）。复核脚本：`Tests/score_probe_real.swift`。

## 怎么用

### 方法一：下载编译好的 App（推荐）

从本仓库 [Releases](https://github.com/Dyingdong/photography_photo_selection_assistance_software/releases) 下载 `FocusScreener-v1.0-arm64.zip`，解压双击即可。当前发布包为 **Apple Silicon（arm64）** 版本。

若提示"来自身份不明的开发者"，右键 → 打开 → 弹窗里点打开；或执行：

```bash
xattr -cr "/path/to/摄影照片筛选工具.app"
```

### 方法二：从源码编译

需要 Apple Silicon Mac，以及 Xcode 命令行工具（`xcode-select --install`）：

```bash
git clone git@github.com:Dyingdong/photography_photo_selection_assistance_software.git
cd photography_photo_selection_assistance_software
./build.sh
```

`build.sh` 会编译 GUI App 和命令行工具 `focuscli`，并把内置的 exiftool 打进 App 资源里。用 `ditto` 打包 App 可保留 macOS 扩展属性：

```bash
ditto -c -k --sequesterRsrc --keepParent "摄影照片筛选工具.app" FocusScreener.zip
```

### 界面操作步骤

1. 把照片文件夹拖进窗口，或点"选择文件夹"；也可一次拖入多张照片。
2. 左侧默认"只看未合焦"，取消勾选可看全部；点某张在右侧查看。
3. 看热力图判断主体锐度；**滚轮向下滚动放大、向上滚动缩小（以鼠标所在位置为中心）**。放大/平移/圈选的手势如下：
   - **⌘ + 左键拖框** = 放大选中的区域（可继续框选放大）；**右键拖框**同样放大。
   - **按住左键拖动** = 平移画面（放大后移动查看；按住空格再拖也可以）。
   - **单击** = 复位到 1×。
   - **双击** = 放大到相机对焦点所在区域（无对焦点数据时退回主体框）。
   - 信息区「判断依据」里的指标全部直接显示（主体清晰度、画面中心清晰度、合格线、发虚区域、拖影等），鼠标停上去有白话解释。
4. 自动主体定位不准时，**按住 ⌃ Control + 左键拖框圈出主体**重判这一张。
   - 各手势的修饰键可在顶部「**快捷键**」面板里改（例如把圈选主体改成 ⌥ Option 或 ⇧ Shift）；若系统开了「Control + 点击 = 右键」，⌃ 会被系统拦截，改用它即可。
5. 底部调灵敏度（严格/标准/宽松）会即时重算全部结果。
6. 看**综合评分区**：确认题材对不对（自动识别不准就手动改），看建议星级和各维度得分；想看构图就打开预览工具栏的「**九宫格**」「**对角线**」（默认关，可同时开叠加）。
7. 认可建议就点「**采用建议：打 N 星**」写入 Bridge 星级；也可直接在最上面的星标条手动打分或点"拒绝"。确认后点"写入 Bridge 元数据"，或点"导出 CSV 报告"；要删片用底部"删除当前照片"。

### 命令行批量处理

`build.sh` 生成的 `focuscli` 与 App 共用同一套判定和报告格式：

```bash
./focuscli /path/to/photos -o report.csv -s 1.0
```

参数：`-o` 输出 CSV、`-s` 灵敏度（默认 1.0）、`-a` 指定清晰参考片（可选，默认不需要）、`--faces` 优先按人脸定位主体。

### 用真值复核

`Tools/verify.py` 提供四个子命令：

- `truth`：用人工真值算混淆矩阵、临界样本、建议灵敏度
- `drift`：检验判定是否依赖批次构成
- `degrade`：模糊梯度，检验分数与判定的单调性和拐点
- `bytes`：检查写入的 XMP 是否合法、字段齐全、结构完好

仓库内的 `真值-real_v5.xlsx`、`真值-整理版50张.csv`、`标定样本画像.csv` 是标定和复核用的样本数据。

## 边界与注意事项

- **判定是辅助，不是结论。** 它是基于 50 张真值样本调出来的经验规则，换机型/镜头/题材后应重新标注标定；临界片一定要人眼看一眼再决定是否删。
- 热力图是相对参考，不是相机 K 值或测光表；灰块表示该处纹理不足、无法判断。
- 对焦点目前主要支持 Canon RAW，其他来源仅供参考或没有数据。
- 白平衡是颜色统计倾向，不是色温 K 值。
- 模糊和景深不足、运动模糊在画面上表现相近，工具会给出区分提示，但最终取舍仍需结合拍摄意图。
- 写入元数据前会自动备份；RAW 只写侧车文件，不改动原片。评分/拒绝会单独备份原 XMP 到同一备份目录。
- 删除会进废纸篓而非直接抹除，但废纸篓容量有限，清空后不可恢复，删片前仍建议确认。
